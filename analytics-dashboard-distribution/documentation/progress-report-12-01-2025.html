Architecture Notes

State Management Pattern

The application uses a centralized state object with getter/setter pattern. State changes trigger re-renders of affected components. No external framework - pure vanilla JS.

Data Flow

Store × Week × Promotion records → aggregated by MockData getters → consumed by app.js → rendered to DOM. The atomic record structure supports flexible aggregation at any entity level.

Caching Strategy

IndexedDB with TTL-based expiration. Cache-first fetch strategy with automatic retry on failure. Periodic cleanup of expired entries (every 5 minutes).
